## Описание проекта

Цель проекта — разработка веб-сервиса, который автоматически собирает данные из открытых источников и анализирует упоминания брендов, продуктов или знаменитостей. Сервис также оценивает отношение к объекту на основе тональности найденной информации и предоставляет визуализацию изменений этого отношения с течением времени. Для удобства пользователей интегрирован Telegram-бот, через который можно получать результаты анализа.


# MVP
aka 4 чекпоинт
## TL;DR
Запуск сервера и веб-приложения.
Из корня репозитория:
```
docker-compose build
docker-compose up
```

Сервер запускается на порту ```8000```, клиент на порту ```8501```.
Для обучения baseline модели нужен датасет в формате CSV. Например, [такой](https://disk.yandex.ru/d/A5dKlsZhXPuDZw).

## Сервер
Сервер представляет собой FastAPI приложение, позволяющее обучать модели для классификации текстов, а также производить предикты с помощью обученных моделей.

### Описание API
OpenAPI схема находится в файле [openapi.yaml](server/docs/api/openapi.yaml).
Сервис поддерживает следующие HTTP методы:
- `GET /` - ручка, отдающая статус сервиса.
- `POST /api/v1/models/fit/upload_csv` - ручка для загрузки датасета для дальнейшего обучения на нем. В MVP поддержан только формат CSV. В качестве обязательного аргумента принимается `operation_id` - id операции обучения(эксперимента), он же ожидается в запросе в ручку `/api/v1/models/fit` для определения, на каких данных требуется обучать модель.
- `POST /api/v1/models/fit` - ручка, запускающая обучение выбранной версии модели на ранее загруженном датасете (по `operation_id`) с учетом запрошенных гиперпараметров. Из-за специфики пайплайна обучения, таймаут установлен в 10 минут.
- `POST /api/v1/models/predict` - предсказание выбранной модели на основе данных из запроса. В MVP принимается список строк.
- `POST /api/v1/models/set` - установление текущей модели для инференса. В MVP поддержана только одна модель - `baseline`.
- `GET /api/v1/models/models` - получение списка актуальных моделей на сервере со статусами обучения.

### Иерархия директорий и компоненты системы
Код лежит в директории `/server`.

Файл [main.py](/server/main.py) - основной исполняемый файл.

В директории `/server/docs` лежат схемы API.

Директория `/server/models` содержит код моделей (с методами `fit`, `predict`, а также логикой сериализации-десереализации моделей для дампов на диск).

`/server/app` - основные компоненты сериса - хранилище датасетов, роутер http-запросов (и pydantic-схемы), менеджер моделей.

### Работа с диском
Сервер рассчитан на запуск внутри docker-контейнера, и пишет/читает в следующие директории:
 - `/logs` - директория для логов приложения.
 - `/models` - директория для хранения предобученных моделей.
 - `/datasets` - директория для хранения датасетов для обучения.
 - `/data` - директория для хранения данных, необходимых для работы пайплайна обучения (предобученные библиотечные модели и прочее).

## Клиент
Клиент представляет из себя Streamlit-сервис, поддерживающий HTTP API сервиса.

### Страницы
- `Upload and fit` Страница позволяет загружать датасеты для обучения, демонстрирует некоторые данные о датасете, также реализован выбор гиперпараметров обучения. По клику пользователя происходит запуск обучения выбранной модели на предоставленном датасете
- `predict` Страница для получения предсказаний от выбранной модели на основе предоставленных данных.

### Работа с диском
Сервер рассчитан на запуск внутри docker-контейнера, и пишет/читает в следующие директории:
 - `/logs` - директория для логов приложения.
